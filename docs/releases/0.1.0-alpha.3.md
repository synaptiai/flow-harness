# Flow 0.1.0-alpha.3 release notes

Flow `0.1.0-alpha.3` preserves the `0.1.0-alpha.2` usability checkpoint and corrects the public npm
package identity to `@synapti/flow-harness`. This version is the first Flow preview intended for
publication through the `synapti` npm organization.

## Install the preview

Install this exact release and confirm the public executable:

```sh
npm install --global --ignore-scripts @synapti/flow-harness@0.1.0-alpha.3
flow --help
```

Follow
[Install the Flow preview](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.3/docs/guides/install-preview.md)
to use the moving `preview` channel, verify the immutable GitHub assets, resolve installation
problems, and complete a credential-free run. The guided path requires no model credential, Docker
Engine, Bun, or Prime runtime.

## Package-identity correction

The immutable `0.1.0-alpha.2` GitHub release contains the package name
`@synaptiai/flow-harness`. npm rejected that name because the corresponding organization scope
doesn't exist. The rejected request created no npm package, version, or distribution tag.

`0.1.0-alpha.2` remains a GitHub-only historical release. Flow preserves its verified assets
without modification. This release advances the semantic version. The corrected manifest,
archive, release evidence, GitHub provenance, and npm registry artifact can now identify the same
bytes.

## Usability checkpoint

- `flow quickstart` creates a minimal project without replacing an existing Flow configuration.
  It runs one credential-free workflow and returns explicit `inspect` and `web` commands.
- `flow doctor` checks only the selected host, project, workflow, provider, sandbox, or Prime path.
  It returns fixed problem categories and remediation without printing credentials or private
  paths.
- `flow web` presents an accepted run through a local, capability-bound browser session. The quick
  start never opens a browser automatically.
- The package includes the generated public capability catalog and versioned workflow and evidence
  contracts. It also includes evaluation, proof-verification, and bounded-delegation surfaces.

## Supported environment

- Node.js 26.7.0 or newer.
- Linux and macOS package launchers.
- Release qualification on GitHub-hosted Ubuntu 24.04 x64 and macOS 15 Intel.

Windows isn't supported. Other Linux and macOS architectures aren't release-qualified in this
version. Agent `exec`, the container command profile, Prime Agent, and Lean proof verification have
narrower Linux x64 requirements. Read
[Project status](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.3/docs/project-status.md)
before you select one of those paths.

## Included verification

The release workflow builds one archive and requires that exact archive to pass these checks on
both release-qualified hosts:

- Archive bounds, installed-file identity, package metadata, and clean consumer dependency
  resolution.
- Command discovery, public help, and a complete installed `flow quickstart` run.
- Read-only `flow doctor`, durable evidence inspection, and the explicit local browser path.
- Public capability catalog agreement and the expected Prime host-preparation boundary.

GitHub build provenance binds the archive and release-evidence document to the source revision and
preview workflow. The release includes a complete file manifest and SHA-512 archive digest.

npm fetches Flow dependencies during installation. The archive contains the reviewed
`npm-shrinkwrap.json`, and release qualification tests the closure that npm resolves on both
supported hosts. Artifact verification doesn't prove that a later registry response is identical.

## Compatibility and security limits

This prerelease doesn't promise workflow, configuration, storage, or migration compatibility with
a later preview. It isn't a hostile-workload or multi-tenant security boundary. The native sandbox
and optional container or Prime profiles retain the boundaries in the
[security policy](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.3/SECURITY.md).

The release doesn't include automatic updates, a hosted service, provider credentials, or learned
production routing. It also excludes production context compaction, production dynamic
delegation, remote ACP authority, and multi-host supervisor control. Evaluation-only features
can't activate themselves.

The npm channel uses the `preview` distribution tag. Because this is the package's first public npm
version, npm also exposes this version through `latest` even though publication used
`--tag preview`. Unqualified installs therefore resolve to alpha.3. Use `@preview` explicitly. The
first stable release will move `latest` to the stable version.
