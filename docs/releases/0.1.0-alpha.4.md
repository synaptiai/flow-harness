# Flow 0.1.0-alpha.4 release notes

Flow `0.1.0-alpha.4` is the first compatibility-governed usability checkpoint. It preserves the
guided installation and first-run path from `0.1.0-alpha.3`, adds a read-only compatibility check,
and makes the package's CLI-only boundary explicit and release-tested.

## Install the preview

Install this exact release and confirm the public executable:

```sh
npm install --global --ignore-scripts @synapti/flow-harness@0.1.0-alpha.4
flow --help
flow compatibility check
```

Follow
[Install the Flow preview](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.4/docs/guides/install-preview.md)
to use the moving `preview` channel, verify the immutable GitHub assets, resolve installation
problems, and complete a credential-free run. The guided path requires no model credential, Docker
Engine, Bun, or Prime runtime.

## Compatibility boundary

- `flow compatibility check` verifies an immutable package-owned corpus without reading a project,
  credentials, network service, or mutable user state.
- The initial corpus binds one authored workflow and one terminal run ledger from the immutable
  `0.1.0-alpha.1` release. The report uses fixed result categories and contains no source content,
  command output, timestamp, credential, or filesystem path.
- The npm package exposes one supported entry point: the `flow` executable. Its empty `exports` map
  rejects package-root and undeclared-subpath imports.
- Compiled JavaScript files and declarations remain internal even though the release archive needs
  them to run the CLI.
- The [compatibility policy](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.4/docs/compatibility.md)
  classifies the CLI, authored schemas, public output, durable records, capability packages,
  presentations, and internal modules separately.

## Library API decision

This release doesn't add a supported JavaScript or TypeScript library API. A reproducible source
audit covers all 320 production modules and 2,938 exported internal declarations. It also covers
six candidate entry points, 92 documented CLI forms, and direct JSON output sites in the CLI
composition root.

The first possible library remains a separately versioned, read-only workflow-validation package.
It requires evidence from at least three independent consumers. It also requires a smaller public
summary, stable diagnostic codes, fixed resource limits, and differential compiler tests. The
package must pass packed-consumer tests and have no ambient authority. A versioned process protocol
must exist before Flow adds a typed client for execution and long-running control.

Read the
[library API assessment](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.4/docs/library-api-assessment.md)
before you depend on an internal module or propose an in-process integration.

## Included verification

The release workflow builds one archive and requires that exact archive to pass these checks on
GitHub-hosted Ubuntu 24.04 x64 and macOS 15 Intel:

- Archive bounds, installed-file identity, package metadata, and clean consumer dependency
  resolution.
- Command discovery, public help, and a complete installed `flow quickstart` run.
- Read-only `flow doctor`, durable evidence inspection, and the explicit local browser path.
- Generated public capability agreement, the Prime preparation boundary, the compatibility corpus,
  and rejection of unsupported package imports.

GitHub build provenance binds the archive and release-evidence document to the source revision and
preview workflow. The release includes a complete file manifest and SHA-512 archive digest.

The separately recoverable npm workflow downloads the immutable GitHub assets again. It verifies
the release, assets, provenance, source revision, installed package, and unused npm version. It then
uses GitHub OpenID Connect to create a staged publication. A maintainer must inspect and approve the
stage with two-factor authentication before the version becomes public.

## Supported environment

- Node.js 26.7.0 or newer.
- Linux and macOS package launchers.
- Release qualification on GitHub-hosted Ubuntu 24.04 x64 and macOS 15 Intel.

Windows isn't supported. Other Linux and macOS architectures aren't release-qualified in this
version. Agent `exec`, the container command profile, Prime Agent, and Lean proof verification have
narrower Linux x64 requirements. Read
[Project status](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.4/docs/project-status.md)
before you select one of those paths.

## Compatibility and security limits

This alpha proves only the classified surfaces and corpus observations in the compatibility policy.
It doesn't promise that every workflow, configuration, durable record, or internal module from an
earlier preview works unchanged. It provides no automatic migration.

Flow isn't a hostile-workload or multi-tenant security boundary. The native sandbox and optional
container or Prime profiles retain the boundaries in the
[security policy](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.4/SECURITY.md).

The npm prerelease channel is `preview`. npm's first-publication exception left `latest` on
`0.1.0-alpha.3`. This release must not move it. Use `@preview` or the exact version. The first stable
release will move `latest` to the stable version.
