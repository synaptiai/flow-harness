# Flow 0.1.0-alpha.1 release notes

Flow `0.1.0-alpha.1` is the first installable public preview. It packages the existing standalone
harness as the `flow` command without changing the pre-stable workflow format.

## Install the preview

Follow [Install the Flow preview](../guides/install-preview.md) to verify the immutable release and
complete a credential-free run.

## Supported environment

- Node.js 26.7.0 or newer.
- Linux and macOS package launchers.
- Release qualification on Ubuntu 24.04 x64 and macOS 15 Intel.

Windows isn't supported. Other Linux and macOS architectures aren't release-qualified in this
version. Some execution profiles have narrower requirements. Prime and the container command
profile require the documented Linux x64 environment.

## Included verification

The release workflow builds one archive and then verifies these behaviors from that archive on
both release-qualified hosts:

- Installed file identity and package metadata.
- Command discovery and `flow --help`.
- Project initialization and effective configuration.
- A credential-free deterministic command workflow.
- The local browser presentation path.
- Prime example validation up to its expected host-preparation boundary.

The release includes a complete file manifest and SHA-512 archive digest. GitHub build provenance
binds the archive and evidence document to the release workflow and source revision.

## Compatibility and security limits

This prerelease doesn't promise workflow, configuration, storage, or migration compatibility with
a later preview. It isn't a hostile-workload or multi-tenant security boundary. The default native
sandbox and optional container or Prime profiles retain the boundaries in the
[security policy](../../SECURITY.md).

The preview doesn't include automatic updates, `flow doctor`, `flow quickstart`, a hosted service,
or provider credentials. Read the [delivery roadmap](../roadmap.md#gate-8-usable-public-preview)
for the next usability slices.

The release uses the npm `preview` distribution tag. It doesn't assign `latest`.
