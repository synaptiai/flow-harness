# Flow 0.1.0-alpha.2 release notes

Flow `0.1.0-alpha.2` is the usability checkpoint for the public alpha. It adds a guided first run,
read-only environment diagnostics, and a local browser follow-up. The package also includes the
Gate 9–10 capability and evaluation surfaces.

## Install the preview

Follow
[Install the Flow preview](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.2/docs/guides/install-preview.md)
to verify the immutable GitHub assets, install the exact archive, and complete a credential-free
run. The guided path requires no model credential, Docker Engine, Bun, or Prime runtime.

## Usability improvements

- `flow quickstart` creates a minimal project without replacing an existing Flow configuration. It
  runs one credential-free workflow and returns explicit `inspect` and `web` follow-up commands.
- `flow doctor` checks only the selected host, project, workflow, provider, sandbox, or Prime path.
  It returns fixed problem categories and remediation without printing credentials or private
  paths.
- `flow web` presents an accepted run through a local, capability-bound browser session. The
  quick-start command never opens a browser automatically.
- The installed package includes the generated, versioned public capability catalog and readable
  reference. Package verification rejects stale generated documentation.
- The package includes the current workflow, durable evidence, recovery, and portable-capability
  contracts. It also includes the documented evaluation, phase-routing, context-compaction,
  proof-verification, and bounded-delegation contracts.

## Supported environment

- Node.js 26.7.0 or newer.
- Linux and macOS package launchers.
- Release qualification on GitHub-hosted Ubuntu 24.04 x64 and macOS 15 Intel.

Windows isn't supported. Other Linux and macOS architectures aren't release-qualified in this
version. Agent `exec`, the container command profile, Prime Agent, and Lean proof verification have
narrower Linux x64 requirements. Read
[Project status](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.2/docs/project-status.md)
before you select one of those paths.

## Included verification

The release workflow builds one archive and requires that exact archive to pass these checks on
both release-qualified hosts:

- Archive bounds, installed-file identity, package metadata, and clean consumer dependency
  resolution.
- Command discovery and public help.
- A complete installed `flow quickstart` run through the production command sandbox.
- Read-only `flow doctor` checks that don't mutate the quick-start project.
- Durable evidence inspection and the explicit local browser path.
- Public capability catalog and reference agreement.
- Prime example validation through the expected host-preparation boundary.

GitHub build provenance binds the archive and release-evidence document to the source revision and
preview workflow. The release includes a complete file manifest and SHA-512 archive digest.

npm fetches Flow dependencies during installation. The archive contains the reviewed
`npm-shrinkwrap.json`, and release qualification tests the closure that npm resolves on both
supported hosts. Artifact verification doesn't prove that a later registry response is identical.

## Changes from 0.1.0-alpha.1

The first alpha remains immutable historical evidence. It doesn't contain `flow quickstart`,
`flow doctor`, or the later Gate 9–10 capability surfaces. Use its versioned release notes and
installation path only when you intentionally evaluate that archive.

`0.1.0-alpha.2` doesn't provide an automatic migration from an earlier preview. Back up state that
you need to retain, install the new version, and start a new evaluation project.

## Compatibility and security limits

This prerelease doesn't promise workflow, configuration, storage, or migration compatibility with
a later preview. It isn't a hostile-workload or multi-tenant security boundary. The native sandbox
and optional container or Prime profiles retain the boundaries in the
[security policy](https://github.com/synaptiai/flow-harness/blob/v0.1.0-alpha.2/SECURITY.md).

The release doesn't include automatic updates, a hosted service, provider credentials, learned
production routing, or production context compaction. It also excludes production dynamic
delegation, remote ACP authority, and multi-host supervisor control. Evaluation-only features can't
activate themselves.

The npm channel uses the `preview` distribution tag. It doesn't assign `latest`.
